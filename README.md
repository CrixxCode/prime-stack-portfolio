# Digital Blueprint

Build a polished personal portfolio website for a Full-Stack Developer. The site must feel like a premium digital product designed by someone who understands software engineering, architecture, UX and product—not a generic developer template.

IDENTITY
- Core words: Innovador · Minimalista · Profesional.
- Inspiration: Vercel, Discord, modern SaaS, Apple, restrained futuristic design, moderated modern brutalism.
- Do NOT copy those brands.
- Avoid black+purple cliché, neon cyberpunk, matrix, fake terminal, space backgrounds, permanent particles, huge technology logos, excessive glassmorphism, percentage skill bars, overuse of cards.

PROFILE CONTENT
- Role: Full-Stack Developer.
- Main strengths: Django + Angular.
- Also works with/has experience with: Python, ASP.NET Core, .NET, React, Node.js, TypeScript, JavaScript, PostgreSQL, MySQL, SQL Server, Docker, Git, Postman, WSL.
- Message: preferred technologies exist, but value comes from fundamentals and ability to adapt fast to new stacks.
- Education: Ingeniería de Sistemas, Universidad de La Guajira, final stage of degree.
- Interests: software architecture, web development, software engineering, AI.
- English level: B2.
- Experience: Full-Stack developer at ALGORITHM S.A.S., June 1, 2026 – Present. Keep company work descriptions generic and do not expose private/internal projects.
- Achievements: strong Saber Pro performance, winner of a university hackathon, top 10 in a national hackathon.
- Do not invent years of experience, certificates, repository counts, contribution counts, or other stats not given.

PROJECTS
Use two public-safe featured projects:
1) Academic hotel management platform for Riohacha — full-stack web platform for hotel information management, reservations, clients, rooms, billing/reporting concepts; position as academic/product case study.
2) UniguajiraTest — Saber Pro preparation/evaluation platform with practice, diagnosis, training, mock exams, feedback and analytics.
Do not use any private company repository. Repo links should remain hidden or shown as “Private / not public” unless a real URL is supplied later.

VISUAL SYSTEM
Create both Light and Dark modes as intentionally designed variants.
Dark:
- bg #0A0A0B
- surface #111214
- secondary surface #17181B
- warm-white primary text, cool-gray secondary text
Light:
- warm off-white background, light gray surfaces, subtle low-contrast borders, charcoal text
Accent:
- restrained electric blue / tech cyan in range #4F7CFF, #3B82F6, #22B8FF
Use accent for CTA, links, active states, small indicators only.
Gradients only extremely subtle.

TYPOGRAPHY
Use a modern sans similar to Geist/Inter/Manrope, with monospace only for metadata/tags/technical labels. Strong typographic hierarchy through scale and composition, not effects.

LAYOUT
- Consistent grid, generous whitespace, thin borders, subtle shadows, medium radius, wide sections.
- Controlled asymmetry.
- Mix open editorial sections, large project showcases, technical dashboard-like module, and a few cards.
- Some sections may be near 100vh: Hero, featured projects, GitHub, Contact.
- Keep natural scrolling; no scroll-jacking.

NAVBAR
Floating centered pill navbar, sticky, compact, subtle blur and border, translucent background.
Items: Inicio, Sobre mí, Experiencia, Proyectos, Stack, Formación, Logros, GitHub, Contacto.
Include ES/EN and Light/Dark controls.
On mobile use an elegant compact menu, preserving clear CTA access.

HERO
No real photo as hero.
Use an abstract editorial avatar/illustration made from CSS/SVG-like geometric composition: grids, architecture nodes, connection lines, small interface panels, coordinates, minimal code metadata. No childish cartoon.
Content:
small label “Full-Stack Developer”
headline: “Construyo productos digitales de principio a fin.”
subheading emphasizing modern, scalable, product-oriented web apps
explicitly mention Django + Angular as strongest stack, while saying stack is flexible
small inline tech row: Django · Angular · .NET · React · PostgreSQL
primary CTA: “Hablemos”
secondary CTA: “Ver proyectos”
status: “● Disponible para oportunidades”
Hero should feel editorial and distinctive.

ABOUT
Editorial layout with optional real-photo placeholder as secondary element. Copy should discuss frontend+backend, complete products, architecture interest, learning new stacks, maintainability, quality, UX.
Highlighted sentence:
“Las herramientas cambian. La capacidad para construir soluciones no.”

STATS
Compact stats using only real data:
- 10+ Tecnologías utilizadas
- 2 Proyectos destacados
- Full-Stack / Frontend + Backend
- B2 / English Level
Allow future extension for years, projects, hackathons, certifications, contributions.

FEATURED PROJECTS
Make this a protagonist section with two large viewport-scale showcases, alternating desktop composition:
Project 1 image left/content right.
Project 2 content left/image right.
Each has screenshot/visual placeholder, name, concise description, problem solved, stack, role, key functions, status, case-study CTA, repository state.
Create premium custom mock screenshots if real screenshots are absent using product UI compositions; no fake browser chrome overload.
Responsive: stack vertically on mobile.

STACK
Organize by domain, not logo cloud:
Backend: Django (Principal), Python (Principal), ASP.NET Core (.NET) (Experiencia), Node.js (Experiencia)
Frontend: Angular (Principal), TypeScript (Principal), React (Experiencia), JavaScript (Experiencia)
Data: PostgreSQL, MySQL, SQL Server
Tools: Docker, Git, Postman, WSL
Use labels Principal / Experiencia / Explorando only when sensible. Never percentages.

TECH ADAPTABILITY BLOCK
Compact visual flow:
Backend: Django → .NET → Node
Frontend: Angular → React
Headline: “Stack flexible. Fundamentos sólidos.”
Communicate fast learning and tool independence.

Generic responsibilities: develop and maintain frontend/backend features, APIs, data integration, debugging, testing, collaboration, product iteration. Do not reveal private project details.

If live data unavailable, mark dynamic fields as placeholders and never fabricate counts.

optional short form: Nombre, Email, Mensaje
accessible labels and validation.

FOOTER
Minimal:
Full-Stack Developer
GitHub / LinkedIn / Email / ES-EN
“Designed & built with intention.”

ANIMATION
Use refined motion throughout: reveal, typography, subtle scale, hover, slight parallax, avatar micro-movement, technical elements. 200–600ms. Spring where appropriate. Must respect prefers-reduced-motion. Animation must communicate hierarchy/interaction, not decoration.

BRUTALIST ACCENTS
Use only in controlled ways: oversized section numbers, strong large titles, rules/lines, unexpected but precise alignment.

ACCESSIBILITY & PERFORMANCE
- WCAG AA minimum
- semantic HTML, keyboard navigation, visible focus, labels, ARIA where necessary, 44px touch targets where appropriate, reduced motion
- optimize with lazy-loading, SVG icons, WebP/AVIF-ready media placeholders, optimized font loading
- avoid heavy dependencies and expensive continuous animation
- keep Core Web Vitals in mind

RESPONSIVE
Design intentionally for desktop, tablet and mobile. Do not merely scale down. On mobile simplify complex layouts, keep typography hierarchy, vertical flow, lightweight animation and easy navigation.

IMPLEMENTATION
Build the actual working site, not a static moodboard. Use the default Lovable TypeScript stack with Tailwind + shadcn/ui where helpful, but avoid making everything look like stock shadcn cards. Create reusable components, CSS variables/tokens for both themes, smooth anchor navigation, working theme toggle and ES/EN content toggle. Make the first load visually complete without external assets.
